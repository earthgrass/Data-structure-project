## 1. 目标与非目标

### 目标

* 以北京工业大学（BJUT）主校区周边若干平方公里为研究范围，构建**真实道路
  有向带权图**；
* 把现有 Phase 1-5 的 `LogisticsGraph` / Dijkstra / CFI / 2-opt / Dashboard
  接到真实道路图上，**不重写算法核心**；
* 继续保持**单车辆闭合回路**与容量 / 时间窗硬约束；
* 明确数据许可、署名与可复现性（数据版本 + 构建脚本 + 指纹）。

### 非目标（本阶段不做）

* 不做全国 / 全北京路网；只做 BJUT 周边小范围；
* 不做实时订单、动态重规划、多车辆或跨车调度；
* 不引入 NetworkX / OR-Tools / numpy / scipy 等算法包；
* 不抓取高德 / 百度地图的批量数据；
* 不把地图瓦片或原始 OSM 大文件提交进仓库。

## 2. 拟用数据源

### 2.1 主数据源：OpenStreetMap（OSM）

| 方式 | 说明 | 适用性 |
| --- | --- | --- |
| Overpass API | 按 bbox 查询 `highway=*`、POI、`maxspeed`、`oneway` 等 | 范围小、字段可控，**首选** |
| BBBike extract | 自定义 bbox 导出 `.osm.pbf` / `.osm.xml` | 可离线、可复现 |
| Geofabrik China | 全国 / 省级 extract | 数据量大，需裁剪，备选 |

建议研究范围（待现场确认）：

```text
西：116.43°E   东：116.53°E
南：39.84°N    北：39.91°N
```

覆盖 BJUT 主校区、平乐园、双井 / 劲松方向的主要道路与周边住宅 / 商业 POI。
最终 bbox 以「校区步行 15 分钟 + 配送可达」为准，写入配置文件而非硬编码。

### 2.2 可选补充数据

* 学校公开的校园地图 / 门岗信息：仅使用公开、允许引用的部分。

### 2.3 明确不采用

* 任何需要绕过登录 / 验证码 / 反爬的数据源。

## 3. 道路图构建方式

### 3.1 处理流水线

```text
OSM extract (bbox)
  → 解析 way / node / relation
  → 过滤可行驶道路
  → 处理单行道 / 环岛 / 禁行 / 限速
  → 交叉口拆分 + 节点去重
  → 计算边长（haversine）
  → 生成 distance / travel_time / cost 三套边权
  → 接入 POI（校门 / 客户点）并吸附到最近道路
  → 强连通性检查（取最大强连通分量）
  → 独立 validator
  → ScenarioBundle（复用现有 loader 契约）
```

### 3.2 道路过滤

保留（按配送车辆可行驶）：

```text
motorway, trunk, primary, secondary, tertiary,
unclassified, residential, service, living_street
```

默认排除：

```text
footway, cycleway, path, steps, pedestrian,
construction, proposed, track（除非明确允许机动车）
```

规则：

* `access=no/private`、`motor_vehicle=no` 的 way 排除（校园内部道路按实际
  门禁决定）；
* `oneway=yes` 只建正向边；`oneway=-1` 只建反向边；
* `junction=roundabout` 按单向环处理；
* `maxspeed` 缺失时按道路等级给默认速度，并记录 `speed_source`
  （`osm` / `default`）。

### 3.3 节点与边

* 交叉口：同一 OSM node 被多条 way 共享时作为图节点；way 的中间形状点
  默认不建图节点（只用于几何）。
* 可选优化：度为 2 的链压缩为一条边，减少图规模；但必须保留原始几何用于
  可视化。
* 边长：WGS84 经纬度上使用 haversine 大圆距离（见 §4）。
* 边权：
  * `distance` = 大圆距离（km）；
  * `travel_time` = `distance / speed * 60`（min），speed 来自 `maxspeed`
    或分级默认值；
  * `cost` = `distance * unit_price * congestion_multiplier`；
  * 三者均 `>= 0` 且 finite，沿用 `Edge` 的校验。
* 禁止自环、重复边；`LogisticsGraph.add_edge` 现有语义不变。

### 3.4 POI 与客户点

* 候选 POI：校门、教学楼 / 宿舍、周边住宅小区、便利店 / 快递点；
* 每个 POI 通过**垂直投影**吸附到最近的可行驶道路段，插入虚拟节点或复用
  最近交叉口；
* 记录 `snap_distance_m`；超过阈值（例如 100 m）的 POI 拒绝或人工复核；
* 吸附边增加少量服务时间 / 成本，避免“穿墙”直线连接；
* 客户点与订单的映射写入配置，不在源码硬编码。

### 3.5 连通性与可行性

* 构建后先检查弱连通，再取**最大强连通分量**作为可配送子图；
* 仓库（BJUT 校门 / 配送站）与所有客户点必须落在同一强连通分量；
* 复用现有 `validate_generated_scenario` 的七项校验思路，但新增道路来源
  字段（`source=osm`、`extract_date`、`bbox`、`osm_query`）。

## 4. 坐标处理

| 项目 | 方案 |
| --- | --- |
| 原始坐标 | OSM 为 WGS84（EPSG:4326），保留 6 位小数（约 0.1 m） |
| 距离计算 | haversine 大圆距离；短距离可退化为局部等距投影 |
| 可视化 | Leaflet 直接使用 WGS84 / EPSG:3857（Web Mercator） |
| 中国偏移 | 若使用高德 / 腾讯等底图，需要 WGS84 → GCJ-02 转换，且受其条款约束；本项目优先使用 OSM / 无偏移底图 |
| 抽象坐标 | 现有 `Node.x / y` 继续保留，可由经纬度线性投影生成，供算法与旧测试使用；真实经纬度放 `metadata.lng/lat` |
| 精度 | 距离保留 3 位小数（米级），角度保留 6 位小数 |

注意：现有固定场景的 `metadata.viz_source = "beijing_schematic"` 表示示意
坐标；接入真实数据后应改为 `osm` 并记录 extract 元数据，二者不可混淆。

## 5. 许可与合规要求

### 5.1 OSM

* 许可：**ODbL 1.0**（Open Database License）。
* 必须署名：`© OpenStreetMap contributors`，并在项目文档 / 关于页面展示。
* 基于 OSM 构建的派生数据库（含图结构、边权）按 ODbL 的 share-alike 条款
  处理；保留许可文本与修改说明。
* 不把原始 `.osm.pbf` 大文件提交进 Git；只提交构建脚本、bbox、查询语句、
  数据版本与指纹，必要时提交裁剪后的小样本。
* 遵守 OSM Tile Usage Policy：不批量抓取瓦片；课程演示优先使用示意底图或
  合规瓦片服务。

### 5.2 其他数据

* 北京市公共数据：逐项核对许可，保留来源、版本、获取日期；
* 高德 / 百度：未经授权不批量存储、不缓存、不再分发；
* 校园地图 / 门岗信息：只使用公开且允许引用的材料。

### 5.3 仓库卫生

* `data/` 下只放可公开的小样本或构建产物说明；
* 大文件走 `.gitignore`，构建脚本可复现；
* 不提交 API key、token、个人位置数据。

## 6. 交通数据接入方案

### 6.1 第一阶段：静态速度模型（优先）

* 用 OSM `maxspeed` + 道路等级默认速度；
* 可选按时段（早高峰 / 平峰 / 晚高峰）设置速度系数；
* 所有系数写入 JSON 配置，不在源码硬编码；
* `TrafficStatus` 复用现有枚举（`clear / slow / congested / blocked`）。

### 6.2 第二阶段：实时交通（需授权与配额）

* 仅接入提供正式 API、允许课程 / 研究使用的服务；
* 通过适配器把拥堵等级映射为 `congestion_multiplier`，写入边权；
* 缓存 TTL（例如 5 分钟）+ 失败回退静态模型；
* 记录数据时间戳与来源，规划结果标注“含实时交通 / 静态模型”；
* 不做网页抓取，不绕过配额与鉴权。

### 6.3 与现有算法的关系

* Dijkstra / CFI / 2-opt 的接口不变；只替换 `Edge` 的边权与
  `TrafficStatus`；
* 仍然是单车辆闭合回路；动态事件与重规划属于后续阶段，本设计不启动。

## 8. 验收标准（下一阶段实施时）

1. 同一份 OSM extract + 同一份配置 → 完全相同的图与指纹（跨进程可复现）；
2. 仓库与全部客户点位于同一强连通分量；
3. 所有客户点吸附距离 ≤ 阈值，超阈值点有明确报告；
4. `distance / travel_time / cost` 三套边权可独立累计，逐 leg 校验一致；
5. 单车辆闭合回路，容量 / 时间窗硬约束，未服务订单如实报告；
6. 许可文本、署名、extract 日期、bbox、查询语句齐全；
7. 现有 495 个 unittest 继续通过（新增测试不计入本轮）；
8. 前端 typecheck / build / 代理联调通过。

## 9. 风险与待确认事项

| 风险 | 说明 | 缓解 |
| --- | --- | --- |
| OSM 数据质量 | 单行道、禁行、校园道路可能缺失或错误 | 人工抽查 + 连通性检查 + 记录数据版本 |
| 坐标偏移 | 国内底图 GCJ-02 与 WGS84 不一致 | 优先 OSM / 无偏移底图；必要时显式转换并记录 |
| 许可 | ODbL share-alike、瓦片政策、API 条款 | 先核对许可，保留署名与许可文件 |
| 数据量 | 北京 extract 过大 | 只用 bbox 小范围 + 裁剪 |
| 实时交通配额 | API 限流 / 收费 / 不可再分发 | 静态模型优先，实时数据可选适配 |
| 图规模 | 真实路网节点数远大于 35 | 链压缩 + 只保留最大强连通分量 + 性能测试 |

# 近邻路网与配送动画

## 本轮变更

新 Dashboard 场景的 JSON 配置选择 `topology="local"`、`nearest_neighbor_count=3`。
旧生成器默认仍为 `random`，旧接口和历史实验不改变语义。

先手写 Prim 构造欧氏距离最小生成树，再合并每个节点主动选择的三个最近邻连接。
距离相同按节点 ID 显式比较，候选使用手写有界插入，不依赖集合迭代或现成排序。
树边全部双向；其余连接按物理道路整数配额生成约 95% 双向连接。
每个方向独立生成权重，保留 road_id、方向 ID 和独立结构验证。
生成复杂度为 O(V²k)，空间 O(Vk+V)。

这里“三个最近邻”是主动选择数：他人选择和连通骨架可能使节点度数超过三。
不承诺完全无交叉，也不将示意坐标当作真实道路。显式道路数量与自然近邻结果冲突时拒绝，
不裁剪骨架来满足预算。具体实现为 `algorithms/spatial_roads.py`；
路网采样、配额和校验分别仍由 scenario_generator 原模块负责。

## 动画与状态一致性

`useDispatchSession` 继续作为唯一请求入口。真实 step 成功后，
`useConfirmedMotion` 使用 requestAnimationFrame 回放上一快照到已确认快照之间的时段。
所有车辆使用同一模拟时钟；仅沿真实当前方向边插值。行驶轨迹逐段显示，装卸/签收动作
显示脉冲，客户节点在有效订单全部实际签收后变色。同址多订单仍逐订单统计。

回放期间保持命令锁，防止轮询覆盖回放快照；结束后统一展示后端确认的位置、载荷、
订单状态和指标。前端不修改物理位置、签收结果或载荷。动画是时间压缩演示，不是 GPS。
0.5/1/2/4 倍速作用于后续动作的展示时长，不改变业务行驶时间；减少动态效果偏好跳过插值。
“暂停动画”展示当前已发出动作的确认结果后停止后续推进，不回滚后端；
车辆业务暂停仍用“下一节点暂停”。暂不提供任意时刻倒放或历史重播。

双向道路底图每对节点仅绘制一次，保留两个方向的真实记录和交通状态；
可关闭底图突出配送路线。新生成规则仅适用于新场景，不改写既有会话图。

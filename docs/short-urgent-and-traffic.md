# 短时紧急订单与模拟路况

## 时间窗口径

新建 Dashboard 场景默认使用 `rush`，只改变运营校园场景的订单时间窗。配置位于 `config/dispatch_bjut_operational.json`：`rush_earliest_offsets_minutes` 表示**从当前模拟时刻到最早服务开始**的分钟数，`rush_window_lengths_minutes` 表示**从最早服务开始到签收完成截止**的分钟数。分别抽样后相加得到截止。固定 Seed 可复现同一批时间窗。

系统初始特急单的窗口开始偏移为 0–9 分钟、长度为 5–14 分钟；紧急单分别为 0–14 分钟、6–19 分钟。两类严格满足“小于 10 / 15 分钟的起点偏移”和“小于 15 / 20 分钟的窗口长度”。普通订单仍有较宽的窗口。`rush` 中特急明确允许迟到签收，但仍优先争取最早可行签收；紧急和普通订单也可真实迟到。规划优先减少高优先级订单迟到，预计与实际签收分开显示。

`rush` 还允许干线车把特急件从仓库直接送到客户，不经中转。干线车的混合任务仍由手写可行插入生成，特急签收在同车低优先级卸货前；原图 Dijkstra、方向道路、Decimal 载重和签收截止由独立验证器重演。新单若在干线车离仓后到达，必须等已进入动作结束并到仓真实装货，不能凭优先级瞬移货物或撤销既有签收。旧 `pressure`/`strict`/`relaxed` 模式保留原两级配送契约。

固定 Seed `0、1、42、100、2026` 分别用 distance 和 cost 规划时，10 份计划均由独立验证器判为有效且接纳 24/24 单；对应的 `3、4、1、3、2` 张初始特急单均由干线车直送，签收动作全部早于干线车的首个低优先级到站卸货。Seed 42 的 O12 在 cost 模式中，原两级路线预计第 14.62 分钟签收，直送路线预计第 8.62 分钟签收。这是固定场景的真实规划记录，不代表任意在途插单都能立即送达或整体最优。

手动新增特急和紧急单默认建议当前时间后 5–15 分钟，可在上述两项上限内调整。`rush` 场景的前端与后端均校验这两个独立条件；其他旧模式的 API 窗口语义保持兼容。手动特急可选择允许迟到。`rush` 是新场景模式，旧会话不会被改写。

## 配送中移单

Dashboard 使用新的 `remove` 命令，允许对尚未签收的订单在配送运行中发起移除。旧 `cancel` API 的“仅仓库未装货”契约保留。移除会暂停后续动作；已经进入的装货、行驶、卸货完成后，在检查点重规划。已装车取消件仍按原始 Decimal 重量占用车辆容量，计划必须把它运回车辆所属仓库或中转站并执行独立可审计的 `return_cancelled` 动作。已到中转站的取消件留在该站库存位置。已经进入签收动作的订单不能撤销，因为该原子签收已开始。订单 ID、历史和实体库存记录不删除；地图的待完成标记移除。

## 路况操作

地图中的配送图道路可点击；点击后路况面板会选中该**有向边**，显示稳定的 `source|target` 编号，直接点“畅通 / 轻微 / 一般 / 严重 / 封路”即可提交变化，反向边可单独选择。路况选择器把当前剩余计划使用的方向边单独放在最上方，并显示数量，避免误选与计划无关的背景边。浅色的地图背景道路仅供定位，不是全部可编辑的配送边。

“定时模拟路况”由用户主动开启。间隔和抽样 Seed 来自运营配置，当前为每 12 秒一次、Seed 42。每轮只从当前计划尚未行驶的方向边中确定性抽取一条，改变到与原状态不同的畅通级别；不会自动封路。浏览器标签隐藏、请求进行中、计划过期或重规划受阻时跳过该轮。关闭开关即停止；切换会话也会停止并重置次数。

自动抽样只是演示事件源。每次变化仍通过已有 FastAPI `traffic` 命令修改真实图边的模拟权重、增加路况版本，并在动作检查点独立验证与应用新计划。已进入的动作按旧承诺完成，历史不回写。自动更新按固定 Seed 与成功更新序号可复现抽样顺序；墙上时钟触发时刻不作为跨进程指纹。底图不是实时交通数据。

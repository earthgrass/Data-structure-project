# 北工大全屏地图与固定配送候选池

## 用户契约与结果

本轮按用户确认采用北工大周边二维真实地图。全屏地图替代总览中的小图卡片；
订单、车辆、场景设置为可收起面板，主界面不再常驻右侧行程和顶部四张大指标卡。
底部保留规划、播放/暂停、倍速和业务检查点暂停。点击候选地点可直接新增订单。

地图不是随机画的点线：使用 2026-11-08 下载并保留的 OpenStreetMap 道路、建筑与
土地轮廓，覆盖 116.465–116.495 E、39.865–39.885 N。采用统一比例的 Web Mercator
投影，北向朝上，支持拖动、缩放与适配。数据在仓库内离线使用，不依赖地图 SDK、
在线瓦片、外部路径规划服务或启动时下载。

道路来自真实 OSM 几何；仓库、中转站和收货点是配置在真实道路节点上的**模拟业务地点**，
不将它们冒充实际仓储设施、商户地址或已有客户。候选池固定为 30 个地点，默认从中
无放回选择 8 个地点生成初始订单；不同 Seed 改变任务，不改变道路和候选点。
动态订单允许同址多单，仍以订单 ID 分配、验证和签收。

## 对象与文件职责

```text
data/bjut/

  build-config.json          区域、道路类型、默认速度、模拟基地与候选池数量
  network.json               确定性导出的固定道路、几何、候选池与地理底图
config/dispatch_bjut.json    真实地图业务配置，继承既有 JSON 载荷/车辆/时窗设置
src/logiroute/
  algorithms/osm_network.py  手写 SCC、道路链拆分、固定地点选择
  dispatch/real_map.py       固定路网加载和新 profile 配置
  dispatch/scenario.py       固定路网/历史随机路网分流与任务采样
  dispatch/session.py        候选引用限制、几何快照；复用原执行和库存逻辑
frontend/src/dispatch/
  components/MapWorkbench.tsx 全屏地图、订单/车队抽屉、控制栏
  components/NetworkCanvas.tsx 道路几何、建筑底图、候选点、车辆与交通图层
  geography.mjs              等比例投影和沿折线弧长插值
```

旧 `POST /api/v2/sessions` 仅传 seed 的行为保留；新增 `profile="bjut"` 显式启用真实地图。
Dashboard 新建场景使用该 profile。原随机生成器、旧单车接口、原调度器与独立验证逻辑保留。
已有随机会话显示切换提示，创建新会话后才换地图，不改写旧场景物理记录。

## 道路构建与算法理由

1. 从原始 XML 解析 node/way；保留配置中可行驶道路类型，排除 way 上显式的
   private/no access、vehicle=no、motor_vehicle=no。
2. 按共享节点、way 端点与区域边界拆分道路链，保留中间形状点作为边几何。
3. 尊重 oneway=yes、-1 和默认单向环岛；不为真实道路强造 95% 双向比例。
4. 使用手写迭代 Kosaraju 保留最大强连通道路分量，保证模拟地点可往返。
5. 无多重边的既有图模型下，同端点方向的平行链保留较短的真实链，记录丢弃数；
   本数据丢弃 2 条平行方向备选，未将两条几何拼接或平均。
6. 按配置模拟基地坐标选择最近道路锚点，再以手写 farthest-first 选择覆盖区域的
   候选道路节点；所有 tie 使用明确的稳定字符串顺序，集合仅作成员判断。
7. 距离沿原始折线逐段计算球面长度；时间使用数值 maxspeed 或显式 JSON 道路等级
   默认速度；成本为配置的单位公里运输成本。现有 Dijkstra 负责所有实际路径。

伪代码：`parse → directed adjacency → SCC → split way chains → preserve direction/geometry
→ collapse parallel endpoint pairs → SCC → place configured bases → choose fixed pool → export`。
手写 DFS/SCC 为 O(V+E)，稳定字符串插入排序最坏 O(V²)；固定候选选择 O(KV)，
整体 O(V²+E+G+KV)，空间 O(V+E+G)。G 为几何点数。既有 LogisticsGraph 是唯一图容器；
中间折线保留在 metadata，不重写图模型或最短路径。

地图运行时为 **329 个路由节点、742 条有向道路、30 个候选点、2 个模拟仓库、3 个模拟中转站**。
其余节点为路由交叉口，前端不将它们画成大配送圆点，也不接受它们作为动态订单目的地。
地理背景含 624 个建筑/土地要素和 510 条上下文道路；背景道路包括不可配送道路，
背景可见不代表调度可通行。车辆和路线都沿可行驶图的实际边几何绘制。

## 动态订单与动画同步

- 新增：点击地图候选点 → 在此新增订单，或打开顶部“订单”面板新增。
- 取消：订单尚在仓库、且未进入装货时可取消；保留 ID 和终态历史。
  已出仓订单不提供物理删除或退货功能，界面明确说明原因。
- 打开订单面板或地图新增表单会停止后续自动播放，便于编辑；已发出的后端动作确认结果保留。
- 新单先进入待处理队列，不能被当作已配送；在途插单需按检查点暂停后重新规划。
- 保留真实载荷、已进入的道路/动作和历史签收，Decimal 容量逻辑不改变。
- 车辆沿真实道路折线按弧长插值；所有车辆使用同一后端确认时段时钟。
  放大地图时，地点、车辆和文字标记保持屏幕尺寸稳定，减少标签遮挡。

## 边界与未验证事项

这是二维离线 OSM 道路快照，不是卫星摄影、三维场景或实时导航；模拟拥堵仍由本系统显式设置，
没有接入真实交通。真实 OSM 单行比例保留，不套用随机图约 95% 双向的配额。
当前未处理 relation 级转向禁令、时段禁行、门禁/施工现场和车辆限高限重，
不能作为真实配送车辆的道路通行授权。背景建筑覆盖和道路标注取决于该次 OSM 数据。
固定收货点采用道路锚点，没有实现住宅楼门口接驳或道路段投影拆分。
五个样本通过不等于任意新增时窗、载荷或封路后都全覆盖；未服务原因仍如实保留。
几何底图随快照传输，当前适合课程演示规模，未做大城市级缓存和压力测试。

数据按 [OpenStreetMap/ODbL](../data/bjut/README.md) 单独署名与许可；项目代码维持原许可。
历史 BJUT 设计存档与真实道路 stash 均未改写，本轮实现以本文为准。

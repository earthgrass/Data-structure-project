# 地图订单标记与路线变化对照

**历史验收说明**：本文保留截至 `70f29e0` 的前端路线对照实现、手动规划流程与实测证据。当前 Dashboard 已改为[订单变更自动停靠与重规划](order-change-replanning.md)：新增／取消后自动在真实检查点处理；已签收、已取消和已过期订单从地图移除，历史身份保留。下文的“签收勾号”和手动重规划步骤描述原版本，不作为当前默认操作说明。

原轮次针对“路线不醒目、看不清订单、新增紧急订单后看不出重规划影响”完善前端。沿用现有真实道路、订单接口、规划器、容量和时间窗契约；该轮不改变配送算法或后端业务状态。界面规范使用 UI-UX-Pro-Max 的物流工作台方案。

当前地图还提供“专注地图”：收起统计、车队与播放浮层以观察道路对照，再通过“退出专注”恢复。这个显示开关不暂停配送；自动流程中的停靠由后端 `order_control` 状态管理。

## 原版地图显示（历史）

初始规划后，地图默认显示全部车辆路线。路线采用车辆身份颜色、白色衬底、加粗实线和方向箭头，降低道路底图的视觉强度。点击车队卡片可突出某辆车；关闭“全部路线”可单独核对该车，尤其适合多车共享道路的情况。

订单用包裹形标记表示，旁边标注订单 ID。紧急/特急订单同时使用文字和 `!` 标识；本轮新增订单有外围强调圈与“新”标签；全部签收的地点显示勾号。空心候选点与已有订单标记区分，候选池仍可按需展开。

同一地点的多个订单共用地理标记并显示数量，每张订单的 ID、优先级、状态、需求和签收窗口分别保留。点击标记查看逐单详情。取消与过期订单从有效地图标记中移除，但在订单状态及变化记录中保留身份；地点数量不能替代订单数量。

## 原版演示流程（手动入口，历史）

1. 新建场景并规划初始路线，查看全部车辆与订单标记。
2. 从订单面板或地图地点新增订单，选择紧急/特急优先级。新增成功后，地图突出新订单，“路线变化”面板打开并保留修改前计划。
3. 此时新订单仍可能是 `pending`。面板显示等待规划，旧计划中的接纳任务不会自动等同于新订单已安排配送。
4. 在合法业务检查点点击“重新规划并展示变化”。如存在进行中的动作，先请求业务暂停并完成已进入动作，再重规划。
5. 后端返回独立验证过的实际计划后，切换“变更前”“当前路线”“变化叠加”。灰色虚线表示移除的方向路段，橙色外描边表示新增方向路段，车辆颜色表示当前路线。
6. 面板列出新增订单的实际接纳/未接纳结果、变化车辆、方向路段计数和服务顺序对照。若容量或窗口导致无法接纳，明确显示原因，不绘制虚构的新增路线。

新增订单可以落在原路线已经经过的地点。因此有时道路几何保持相同，而服务订单、服务顺序或时刻发生变化；逐车详情单独显示这些变化。若此前根本没有计划，界面将新计划作为首次规划，不虚构一条“变更前路线”。

## 对照记录的时间与范围

对照从**当前页面打开后**开始，在前端内存保留，不是持久化历史版本浏览器。刷新页面或切换会话会清除本地对照；后端真实订单、车辆和事件历史保持其自身状态。参数试算创建不同会话时，同样不会把两个会话的路线混成一次同场景变更。

“变更前”仅切换所绘制的路线证据，**不回滚订单状态、车辆实际位置、载货或模拟时钟**。新订单仍以当前事实展示，便于理解为何需要改变原计划；旧路线图层并非过去时刻的完整场景回放。

首次业务变更发生时保留之前的计划。连续新增、取消、优先级或交通变更，在重规划前累计到同一轮对照。新计划应用后，对照冻结，正常轮询与配送动画不会不断改写变化结果；下一次业务变更才建立下一轮基线。延迟旧修订响应被忽略，跨会话结果不复用。

已执行前缀按真实 `action` 事件识别，不凭时钟猜测。变更发生前已完成的路段、等待检查点期间实际完成的已进入动作，从双方可比较的剩余路线中排除，不能把已经走过的道路误报成重规划移除。

## 计数与职责

方向路段按 **车辆 ID + source + target** 比较。A→B 与 B→A 是两条方向；同一车辆重复经过同一方向仅计一个路段；同一路段分别由两辆车使用时，归入各自的比较。新增/移除路段数量不是距离增减，也不是全局物理道路增删数量。

`routeChanges.mjs` 只观察接受的前后快照并提取证据，`order-map.mjs` 只保留逐单身份并组织同址标记，地图和面板绘制这些数据。没有新增最短路径求解器、排序依赖或对原图的写入。采样、容量、优先级、时间窗和独立验证继续由原后端负责。

## 原手动版本的验证证据

本轮前端 Node 脚本共 **215 项断言通过**，其中订单地图新增31项、路线变化新增49项，原135项保留。订单地图断言包含跨中转站与订单标签避让新增的6项。覆盖同址不同订单、重复 ID、优先级和状态、标签避让、首次规划、连续变更、过期/取消、直接重规划、方向区别、同路不同服务顺序、实际已完成前缀、轮询及跨会话边界。

相关 Python 回归 **14 项通过，耗时8.532秒**。本轮是前端展示与证据跟踪改动，没有声称重新运行历史810项全量回归；此前810项结果仍见[运营参数工作台验收](operations-studio.md)。

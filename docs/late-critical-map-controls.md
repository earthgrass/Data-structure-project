# 手动特急迟到接纳与地图操作

## 新增特急单

手动新增特急单默认勾选“允许迟到签收”，并通过 `protect_critical: true, allow_late: true` 调用原子预检。允许填写已经过去、但仍满足 `0 ≤ earliest < deadline` 的窗口。截止时间仍用于展示预计与实际迟到分钟数，不再作为该单的签收硬拒绝条件。取消勾选或省略 `allow_late` 时，沿用原有特急按时签收约束；初始场景的特急单也保持原约束。

预检先复制会话并推进副本中已进入的物理动作，再沿用既有两级规划器和独立验证器。先保留既有承诺，必要时只释放未装车的普通、紧急承诺；既有特急、已进入动作和在途货物受保护。规划器在每个可行中转站对应的末端车之间比较该新单的**预计签收时刻**，然后比较其他迟到指标与距离或成本。因此这里的“最快车辆”指现有车队和候选路径下、完整续程可行且签收最早的末端车；不是欧氏距离最近的车，也不保证全局最优或为特急独占一辆车。仓库到中转站仍由干线车运输，新货物不能凭空出现在末端车上。

载重、道路方向与可达性、已进入动作、其他受保护任务仍须满足。预检失败时 HTTP 422，原会话不变；成功响应的 `critical_admission` 含分配车辆、预计签收、预计迟到分钟数和让位订单。预计签收不当作实际签收；执行后由独立审计核验。若迟到特急降级为紧急或普通，清除其单独的迟到许可。

## 地图操作

地图上的待完成订单标记可以展开逐单详情；未装车且未进入装货动作的订单显示“取消订单”。确认后由后端校验并暂停、重规划，已签收及取消订单不再作为待完成标记显示。地图顶栏“路况”可直接调整道路状态；点击道路或最近一次路况更新标记会打开道路控制面板。拥堵和封路仍按有向道路绘制；路线变化面板显示重规划前后差异。地图状态是后端快照的投影，最终操作权限及可行性由后端决定。

## 验证与边界

新增测试覆盖迟到特急实际签收、过期窗口、最早可行车辆选择、独立验证许可、容量冲突原子回滚、HTTP布尔校验及降级状态一致性。前端测试覆盖取消门禁、最近路况事件与方向性；保留既有测试。模拟路况并非实时交通，主目标路径闭包不枚举所有可能道路，预检找到的方案仍可能因后续交通变化而失效。

# 分页面运营仪表盘

调度总览继续提供全屏地图和路线变化演示。车队管理、订单中心、交通与路线三个工作区读取同一后端配送会话的快照，不建立第二套规划、载荷或路况规则。

## 道路拥堵

“交通与路线”按有向道路分别统计畅通、轻微、一般、严重拥堵与封路数量。路况条和指标卡随 `traffic_version` 更新；异常道路及已应用计划使用的道路列出方向、通行时间、成本和相关车辆。点击路段会同步选中下方真实地图与模拟交通控制。列表按严重程度优先显示前 80 条，其余道路可在地图和道路选择器中查看。当前计划涉及异常路段的计数可能包含等待重规划的旧路线，不能视为新计划已通过验证。

模拟拥堵来自会话中的人工路况事件，不是实时交通服务。修改方向边后由现有后端暂停和重规划流程处理；已经进入的动作保留历史事实。

## 车辆与载荷

“车队管理”展示每辆干线车或末端车的立体示意车辆、当前动作、位置、车上订单数和实际载重/容量。车身仅沿示意轨道按后端动作的起止时刻插值；地图仍是地理位置与实际路径的依据。该页可直接开始配送、单步推进和播放动画。系统的减少动态效果设置会停用车身过渡。

载重来自后端逐车 Decimal 计算结果，前端仅将已经序列化的数值换算为进度条宽度，不参与容量判定。道路拥堵、车辆载重、计划路线和签收状态使用同一会话版本。

## 订单与路线

“订单中心”按特急、紧急、普通，再按签收截止及订单 ID 展示规划关注顺序。这个顺序是候选接纳优先级；并行车辆的实际签收时刻可能交错。已签收、取消或过期的记录放在末尾，仍保留逐订单 ID 身份。

每单详情展示时间窗、重量、中转站、负责末端车辆、预计/实际签收和已应用路线的有向道路示意。干线先于末端显示。同址多单各自占一条记录。预计按时表示当前已应用计划通过验证，实际签收只有完成服务动作后才出现。输入或路况变化使预计证据过时时，隐藏旧预测与路线；未接纳订单显示失败原因，不虚构可送达路径，也不宣称全局无解。下方保留既有新增、取消、过期和筛选功能。

三个页面只使用现有 `/api/v2` 会话读写接口及前端 `useDispatchSession`。示意车辆和逐单路线图是展示层，未改变手写图算法、调度器或后端 API 契约。

# 约 7 分钟课堂演示脚本

准备：启动后端 8000、前端 5172，使用默认 Seed 42 的运营压力场景。模拟分钟和墙钟秒分别解释。车身动画展示已确认动作的回放，签收只能由后端动作完成。

| 时段 | 点击／展示 | 应核对的真实结果 | 数据结构／算法要点 |
| --- | --- | --- | --- |
| 0:00–0:45 | 打开总览，新建校园场景，切换全局和逐车视图 | 北工大周边离线道路、24 张初始订单、3 个运营中转站、1 辆干线车与 3 辆末端车 | 邻接表保存有向边；道路几何来自离线地图，订单和设施位置为模拟业务落点。 |
| 0:45–1:30 | 打开订单和车队页，检查大件订单与车辆容量 | 可找到 20／30 kg 订单；干线 150 kg、末端逐车 50 kg | 订单按 ID 独立追踪，同址多单不会合并；容量以 Decimal 逐车验证。 |
| 1:30–2:15 | 选择 cost 规划，打开订单页与时间轴 | Seed 42 的固定验收中接纳 24／24，普通订单有 7 单预计迟到，特急和紧急均按时；现场以当前后端结果为准 | 特急完成截止是硬约束；紧急与普通允许迟到，候选先比较高优先级迟到数和时长，再比较主目标。切换严格模式可展示全部硬截止对照。 |
| 2:15–3:15 | 开始配送，选干线车，观察中转卸货与末端出发；打开车队页 | 载货与位置随真实动作变化，卸货不计客户签收 | 仓库→中转站→客户两级配送；地图平滑移动是动作回放，不是 GPS。 |
| 3:15–4:15 | 暂停到安全检查点，新增唯一 ID 的特急订单 | 若能按时签收，预检接纳并自动重规划；否则整笔拒绝、提示调整截止，原订单和载货保留 | 先完成已经进入的动作，再重新规划；未装车低优先级承诺可让位，已装货不能瞬移。 |
| 4:15–5:00 | 在道路页选择当前路线使用的有向道路，改变畅通程度，再恢复畅通 | 每次真实状态变化都增加交通版本，自动检查点重规划；路线几何可能变，也可能仅时间或成本变 | 每条方向边独立更新；已进入的道路动作按进入时版本完成，后续使用新版本。 |
| 5:00–5:45 | 查看路线变化、时间轴和运营参数中的超时记录／罚金 | 分清预计迟到与实际晚签收；签收后订单从活跃地图标记移除，历史事件仍可查 | 独立计划验证与历史审计；罚金与运输成本分列，不用完整覆盖冒充全部按时。 |
| 5:45–6:30 | 运行 distance／cost 对照和受控小实例 | 同一输入和同一覆盖口径下比较真实距离、成本及迟到情况 | 现有手写 Dijkstra 与可行插入；小实例穷举只证明该实例，不证明贪心全局最优。 |
| 6:30–7:00 | 打开 README 和验收文档，展示测试、失败案例与限制 | 指出当前测试结果和未接纳原因；明确模拟交通不是实时路况 | 展示可复现 Seed、独立验证、单进程会话限制。 |

如果课堂时间不足，可以单步展示几个真实动作，再打开原始实验记录说明完整执行结果。不要把计划预计签收或截图当作已经发生的实际签收。新建严格对照场景时会使用同一批 Seed 输入，但时间窗政策不同，不能把两种场景的距离或成本差额单独解释成优化率。

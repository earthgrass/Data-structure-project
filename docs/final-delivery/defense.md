# 数据结构与算法课程答辩

## 项目问题与正式业务

LogiRoute将仓库货物送至五个中转点，再由各站绑定车辆送至客户。校园默认六车24单，初始20校内、4周边。求解同时受逐车容量、货物释放时间、订单三级优先级、完成截止、真实有向道路及返仓约束。地图使用离线OSM，设施位置和订单是模拟/近似数据。

每单保留唯一ID；同址不合并身份。货物在仓库、中转站、车辆或已签收四种位置之间按真实动作转移。中转卸货不是客户签收；只有deliver完成才增加已送达数。系统区分 valid/invalid、complete/partial、安全可应用与否。

## 为什么使用这些数据结构

| 结构 | 当前作用 | 选择理由 |
|---|---|---|
| 邻接表 dict→dict | graph/logistics_graph.py 保存有向出边 | 稀疏校园图V342/E768，存储O(V+E)，邻居访问O(outdegree) |
| 反向邻接索引 | 删除节点、入边查询 | 删除仅处理入出邻接，无须扫描所有边；非第二套权重真相 |
| frozen Node、带权Edge | ID、坐标、方向、distance/time/cost | 防止节点偷偷改变；两个方向是不同边，反向不存在就不能通行 |
| 手写索引最小堆 | algorithms/heap.py供Dijkstra使用 | 数组完全二叉树，字典_pos定位，decrease_key上浮O(log V) |
| 手写有序优先队列 | algorithms/order_queue.py，历史Phase2/5入口 | 入队快照排序键，物理尾端为逻辑队首；失效队首明确拒绝，修改先移除再入队 |
| 订单字典 | dispatch State.orders/locations | O(1)平均ID查找，避免用目的地数代替订单数；终态ID不得复用 |
| 单次Paths缓存 | dispatch/algorithms/__init__.py | 一个输入快照内复用(source,target,metric)路径，实例绑定图版本，不跨场景串味 |
| 车辆、货物位置与protected | State/Session | 在途不重置、不凭空回仓；原货物续程必须保留 |
| Action与事件序列 | Session.events、Network历史 | 原子动作可重演；已进入道路使用原版本；独立历史审计核查已发生事实 |

当前两级入口使用手写插入比较来排列接纳候选，并未直接调用历史OrderPriorityQueue。两者业务目标相关，但不能在答辩中谎称所有入口使用同一队列对象。

## 核心算法解释

**Dijkstra。** 从源点距离0开始，其他点为无穷；每次手写最小堆取暂定距离最小的节点，松弛所有合法出边，改进时更新前驱并decrease_key。非负边权保证已确定点不会再被后续路径改善。通过prev回溯真实节点序列。封路先从当前Paths私有图排除；没有另一套最短路径实现。

**路径闭包。** 调度在仓库、中转站、客户之间考虑访问顺序，但实际转移复用原图Dijkstra，记录途经交叉口和边。distance选择距离最短路径，cost选择成本最短路径；传播时间始终取该实际路径的travel_time，不能用几何直线或主目标数字冒充行驶时间。选定闭包路径不可行不证明所有替代路径都不可行。

**最近可行中转站。** 当前两级 plan_dispatch 逐订单按priority/deadline/ID接纳，按中转站到客户travel_time及站ID比较候选。不是几何直线最近；某站试排完整两级路线失败，才试下一个。每次重新检查干线装货、站点释放、末端装货、窗口和返仓。不是任意聚类质心，也不保证全局最优站点分配。

**可行插入。** build_route 每轮枚举全部未选job和所有插入位置，完整重演候选路线，先容量/关键优先级/时间窗/返仓检查，再以(priority,deadline,主目标增量,job ID,index)显式比较。它是每条两级行程内部的插入。历史Phase3 plan_fleet是跨车辆八字段全局插入，二者并存；当前界面走前者，不能直接套用旧算法名称和复杂度。

**三级优先级。** critical同车同批可用货物必须在低级别服务之前；urgent优先参与可行接纳，但不保证跨车辆实际服务时刻全局排序。新critical货物仍在仓库等待合法装载，不会瞬移到在途车上。严格窗口可以使urgent为紧截止normal调整实际服务顺序；不允许用优先级突破容量和完成截止。

**窗口。** 最早时间约束start，deadline约束end=start+service。提前到达等待，后续任务重新传播。Seed42第二教学楼O14需39.66前签收，原顺序46.50才完成，严格顺序37.66完成。因此路线变化有逐单时刻依据。恰好等于deadline合法，超过即拒绝，不用epsilon放宽。

**精确容量。** 从每笔原始需求和每车容量分别转换Decimal，累加、比较全程Decimal，没有float中间求和或epsilon。车队总容量不能证明某辆车可装。JSON只在明确边界将数量变为字符串。

**独立验证。** validation从原输入重演真实道路、方向、装卸、订单归属、签收时间、容量和返仓，不调用候选重演函数；audit从真实已完成事件再重演历史，不拿计划接纳当签收。输入指纹/revision/traffic_version不匹配会拒绝旧计划。API副本事务失败不覆盖有效会话。

## 复杂度（与当前代码对照）

V/E为图节点/边数，N为订单数，H为站数，K为车辆数，A为动作数，U为实际路径端点数，D为单次候选重演的道路规模上界。

| 操作 | 时间 | 空间/边界 |
|---|---|---|
| 图add_node/add_edge/has_edge | 平均O(1) | 图总O(V+E)，无平行边 |
| remove_node | O(indegree+outdegree) | 原地索引清理 |
| 手写堆push/pop/decrease | O(log V) | 堆与位置索引O(V) |
| 非trace Dijkstra | O((V+E)log V) | O(V+E)含图；算法工作量O(V) |
| trace教学输出 | 额外最多O(V²log V) | 现有每轮settled快照，O(V²+E)输出；不能按非trace性能解释 |
| 历史订单队列入队/按ID移除 | O(N) | O(N)；peek O(1)，pop尾部均摊O(1) |
| Paths缓存命中 | 平均O(1) | 最坏O(U²V)保存路径；未命中调用原Dijkstra |
| 行程插入build_route | 保守O(N⁴D+缓存未命中) | O(ND)，源码同口径 |
| 两级逐单接纳plan_dispatch | 保守O(N·H·N⁴D+闭包) | O(ND+U²V)，不声称精确紧界 |
| 独立计划验证 | O(A²+AN)另加输入指纹构造 | O(A+N)；指纹手写排序最坏O(V²+E²+N²) |
| Session.step | O(K+N) | 只完成最早合法原子动作 |
| 历史审计 | O(AN) | O(N+K)工作状态 |
| 严格窗构造 | O(N²+(1+P(1+2S))T+PS(B+N)) | O(B+计划+PSN)；P≤6/S5，T一次规划、B含图状态 |
| 独立小图穷举 | 指数级 | 仅一单一站正权图简单路径组合；不用于生产调度 |

源码扫描中现有 Dijkstra trace 的sorted只用于教学快照输出；graph邻接导出和历史depot初始化也有稳定展示/默认选择排序。这些历史辅助位置并非本轮新引入的核心排序替代；当前两级候选比较、Dijkstra堆与调度排序均手写。本轮保留扫描命中并分类，不声称全仓库字面零sorted。

## 实验怎么讲

- **双目标受控例**：同输入distance距离4/成本18/行驶4；cost距离6/成本6/行驶6，两者独立实际执行完整。4种闭环组合给出此例距离最小4/成本最小6，不能推导一般贪心最优。统一比例校园初始成本没有冲突，本来就可能相同。
- **严格/宽松**：保留历史五seed20次完整执行；本轮A/B重新运行24单。C极小窗0单且partial；D earliest30产生等待；F同址不同截止分别在32/34签收。E展示urgent和critical规则区别，G交通后旧计划失效。筛选过的预约窗样本不是随机总体可配送概率。
- **动态**：装货后新增critical，保留在途位置、货物及ID；新单可能暂未接纳，原货物仍须安全续送。单独完整返仓后再规划新单，可验证后续配送；不能把“已加入队列”说成“已送达”。
- **反例**：历史Phase3固定域枚举5040候选，216全覆盖，贪心只送5/6；口径见原报告7.3。该反例不删除，也不能把5单的较短路线与6单完整路线直接比较优劣。

## 教师常见问题

1. **为什么图是有向的？** 单行方向与反向缺失是硬条件；同一物理路两个方向可有不同权重。
2. **Dijkstra最优为何配送不最优？** Dijkstra只保证选定指标下的一对点路径最优；订单归属/访问排列是组合问题，贪心不全局回溯。
3. **为什么有时绕远更便宜？** 独立模拟道路服务成本不同；成本并非距离的固定倍数，且明确不是真实收费。
4. **车辆到楼下就是已送达吗？** 不是，等待和服务完成才签收，后端事件是唯一事实来源。
5. **中转站卸货能计完成率吗？** 不能；只改变货物位置，末端车还要装载和签收。
6. **为什么不能任意删在途订单？** 货物已被原子装货接纳，取消会破坏守恒；本阶段只允许未进入装货的仓库单取消/显式过期。
7. **如何防止双击或旧请求覆盖？** revision校验+锁+副本事务；前端session/revision与epoch拒绝迟到响应，比较结果绑定输入版本。
8. **当前技术边界？** 单进程内存会话，重启丢失、不支持跨worker共享；路况模拟，OSM不是实时通行许可；站点近似，启发式和筛选样本没有总体保证。
